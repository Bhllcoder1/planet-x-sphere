## 0. SPHEREx cadence (what we know)
- Minimum 4 spectra at every point along the ecliptic; much more redundancy near ecliptic poles [V: https://spherex.caltech.edu/page/survey]
- "A given region is typically completed in a few days. The entire sky is completely sampled twice every year." Four all-sky surveys in 25 months [V: same page]
- FOV 3.5x3.5 deg; each exposure gives one wavelength per object (LVF); successive exposures follow a great circle 90 deg from Sun [V: same page]
- Exposure count per sky position per pass, time gap between exposures, exposure duration: [NV] not stated in any scraped page (MOST schema lists exposure_time, mjd_start/mjd_end columns, so they can be read per image from IRSA metadata [V: https://irsa.ipac.caltech.edu/applications/MOST/instructions.html]).
- Implication [NV, inference]: visits per position are few (order of the 4+ spectra x passes), clustered in a few days, then ~6 months gap. A mover at 8"/yr moves ~0.1" in a few days (0.02 px of 6.15") so WISE 0855-type objects are NOT detectable as motion inside one pass; only across passes ~6 months apart (~4", under 1 px) or across survey years. Best handled as proper-motion catalog cross-match (Gaia/CatWISE-type), not shift-and-stack. Asteroids (arcsec per hour scale, general knowledge [NV]) do move many pixels within a pass, so these are the real target.

## 1. How real projects find movers
| Method | Needs | Fit to SPHEREx |
|---|---|---|
| Backyard Worlds / WiseView: human blink of difference images from time-resolved WISE coadds; found a T5.5 brown dwarf with PM ~0.7"/yr, 0.9 mag below single-exposure limit [V: https://arxiv.org/abs/1705.02919]. Epoch legend +/-/. = epochs added/subtracted/unused in a frame [V: sources\wiseview.md] | coadds at different epochs (flipbook of 4 time frames per press: [NV from news only]) | Good UI model (blink + difference), but SPHEREx epochs are single-wavelength exposures, not coadds. Only useful for slow PM across passes. |
| Shift-and-stack / KBMOD: GPU maximum-likelihood search over trajectories; >1e10 trajectories in stacks of 10-15 4Kx4K images in under a minute on one consumer GPU [V: https://arxiv.org/abs/1901.02492]. Loops over every starting pixel x every velocity [V: https://epyc.astro.washington.edu/~kbmod/alpha/user_manual/search_space.html]. Input: warped images on shared pixel grid + variance + mask, per-visit MJD and PSF width file [V: .../user_manual/input_files.html]. No fixed cadence required [V: AAS abstract via search, https://ui.adsabs.harvard.edu/abs/2019AAS...23325506S/abstract, not scraped]. DEEP: ~100 images single CCD median 576 s on A40, likelihood threshold 7 [V: search snippet of https://arxiv.org/abs/2310.03678; page scraped but not grepped in detail] | >= ~10 images of same field | Fits only if a field has ~10 overlapping exposures within a few days. Needs reprojection to common grid. Per-frame wavelength differs (see section 4). Min image count for KBMOD: [NV]. |

## 2. What IRSA already offers; identifying known objects
- MOST: given an object (name/number/designation/NAIF ID, or user elements, or MPC 1-line) it gets orbit via JPL Horizons and lists images covering predicted positions; datasets include SPHEREx, WISE, ZTF, 2MASS, Spitzer, SOFIA, PTF [V: https://irsa.ipac.caltech.edu/applications/MOST/instructions.html]. Direction: object -> images. It does NOT do field -> objects.
- MOST scripted API: `https://irsa.ipac.caltech.edu/cgi-bin/MOST/nph-most?catalog=...&input_type=name_input&obj_name=...&obs_begin=...&obs_end=...&output_mode=Brief` via curl [V: https://irsa.ipac.caltech.edu/applications/MOST/MOSTProgramInterface.html]. Catalog keyword value for SPHEREx and rate limit: [NV].
- SPHEREx image table has column target_moving ("Positive if moving target") and per-image ra/dec/mjd [V: MOST instructions page]. SPHEREx images are in IRSA ObsCore (target_moving also in tutorial intro).
- 3I/ATLAS page: observed Aug and Dec 2025; offers VOTable of all observations with predicted comet_ra/comet_dec per exposure, wget/curl download scripts, notes low S/N at many wavelengths and that the comet is spatially extended [V: https://irsa.ipac.caltech.edu/data/SPHEREx/docs/comet3iatlas/index.html]. It is a precomputed per-object table, a pattern we can imitate with Horizons.
- No IRSA moving-object detection tool for SPHEREx found in scraped pages [NV that none exists].
- SPHEREx Solar System Object Catalog (SSOC) team: extracting spectra of asteroids; "extracting spectra for moving targets from a scanning mission presents unique data-reduction challenges" [V: https://meetingorganizer.copernicus.org/EPSC2026/EPSC2026-797.html]; SPHEREx expected to detect hundreds of thousands of SSOs at WISE/NEOWISE sensitivity [V: https://arxiv.org/abs/2402.08705]. Check IRSA for an SSOC release before building our own identification [NV].

Known-object APIs (server-side callable: all are plain HTTPS GET; yes from a server, no browser/CORS needed [V by URL form; CORS not checked])
- IMCCE SkyBoT cone search: `https://ssp.imcce.fr/webservices/skybot/api/conesearch.php?-ep=<epoch>&-ra=&-dec=&-rs=<radius>&-mime=json&-output=basic&-observer=500&-filter=120&-objFilter=110&-refsys=EQJ2000&-from=<app>`; epoch range 1889-11-13..2060-03-21; radius 0..36000 arcsec (rs) or SR up to 30 deg for SCS; observer = IAU code (SPHEREx is not an IAU station: use 500 geocenter or a code, parallax caveat [NV]); filter = position-error cut default 120"; json/votable/text/html; also SOAP/POST [V: https://ssp.imcce.fr/webservices/skybot/api/conesearch/]. Ephemeris accuracy "tens of mas" but orbit uncertainty can reach hundreds-thousands of arcsec so user must filter [V: https://ssp.imcce.fr/webservices/skybot/]. DB updated weekly [V: same]. Rate limit: not stated [NV].
- JPL Horizons API: `https://ssd.jpl.nasa.gov/api/horizons.api?format=json&COMMAND='..'&EPHEM_TYPE=OBSERVER&CENTER=..&START_TIME=..&STOP_TIME=..&STEP_SIZE=..&QUANTITIES=..` GET or POST; TLIST up to 10,000 discrete times; 400 for bad request, 503 under overload [V: https://ssd-api.jpl.nasa.gov/doc/horizons.html]. Per-object only (needs name), not a cone search. Rate limit: not stated on that page [NV]. SPHEREx as observer site in Horizons: not found [NV].
- JPL SBWOBS API (`https://ssd-api.jpl.nasa.gov/sbwobs.api`): lists objects observable from an MPC-code observatory on a night with vmag/elongation filters; not a field cone search, so poor fit [V: https://ssd-api.jpl.nasa.gov/doc/sbwobs.html]. Also JPL SB Identification API exists [NV, not scraped; verify ssd-api.jpl.nasa.gov/doc/sb_ident.html].
- Recommended: SkyBoT per exposure (time = mid-exposure from header/ObsCore mjd), cache results by (field, epoch bin) because each IRSA image is a fixed epoch and static.

## 3. Proposed per-field candidate finder (server, GPU optional)
Input: RA/Dec/radius (<= ~0.5 deg), IRSA SPHEREx image list for the field (ObsCore via TAP sync: `https://irsa.ipac.caltech.edu/TAP/sync?QUERY=...` [V: https://irsa.ipac.caltech.edu/docs/program_interface/TAP.html]; spherex table name [V in sources/irsa-tut-spherex-cutouts.md, re-check]).
1. Cutouts via IRSA cutout service (sources/irsa-spherex-docs-cutout-tool.md); keep FLAGS, VARIANCE, per-pixel wavelength (WCS-WAVE), PSF header (PSF_FWHM exists [V: intro tutorial]).
2. Per-frame detection: background subtract, matched filter with frame PSF FWHM, threshold ~5 sigma, centroid. Output a catalog (x,y,t,flux,lambda,snr). CPU is fine (small cutouts).
3. Static removal: (a) cross-match with Gaia (+2MASS/AllWISE) propagated to epoch; (b) catalog-level: positions that recur within ~1 px in >= 2 frames are static; (c) image-level alternative: per-wavelength-neighbourhood median of reprojected frames (NEOSSat-style median subtraction, sources/github-neossat-tutorial.md) only where >= 4-5 overlapping frames exist. Mask residuals of bright stars (PSF wings, ghosts: flag GHOST_FPA exists [V: intro tutorial]).
4. Known-object tagging: SkyBoT per epoch, match within max(3 px, ephemeris error); remove or label as "known: name". Remaining = candidates.
5. Linking, catalog-space (primary, cheap): all pairs of remaining detections from different exposures with dt in allowed window -> implied velocity v in [vmin, vmax] (vmax set by frames: e.g. 0..~10 arcsec/min [NV choose from the exposure interval]); fit linear (or great-circle) motion per candidate pair set; accept tracks with >= 3 detections within residual < 1 px (use hypothesis grid or Hough/RANSAC on (x,y,t)). Grid step: velocity step * T_total <= ~1 px (KBMOD grid logic [V: search_space page]). Only 2 detections: label "low confidence tracklet" (HelioLinC uses >=2 per tracklet [V]).
6. Pixel-space shift-and-stack (secondary, only for faint things): for fields with >= ~8 overlapping frames, KBMOD-style: warp to common grid, normalise each frame (see 4), grid over (vx, vy), sum likelihood ((sum f/var)/sqrt(sum 1/var)), keep peaks > ~7 sigma [DEEP used 7, V via snippet], then verify.
7. Scoring: sum of per-detection SNR, number of detections, chi2 of linear fit, flux-vs-wavelength smoothness (asteroid reflectance varies smoothly [NV]) and consistency with a rigid-body motion (constant speed). Optionally digest2 on tracklet [V: arXiv 1904.09188].
8. False-positive control: require >= 3 detections or 2 + low-confidence label; mask edges and flagged pixels; reject tracks starting/ending at same pixel in different detectors (persistence/ghosts); rate of random tracks estimated by running the same finder on time-scrambled (shuffled epochs) or velocity-flipped data and reporting the empirical false-track count; cosmic-ray rejection by requiring PSF-like width; compare against SkyBoT density.
9. Output: candidate table + blink strip (WiseView-like epoch legend) + link to MOST for the object once identified.

GPU value (my assessment, [NV] without benchmarks on SPHEREx):
- Truly benefits: step 6 (pixel-space grid x pixels x frames; this is the KBMOD workload, 1e10 trajectories in a minute on one GPU [V: arXiv 1901.02492]); warping/reprojection of many frames; matched-filter convolution if processing hundreds of frames.
- Little/no benefit: step 2 on a few small cutouts (I/O and IRSA download dominate), steps 3-5 catalog linking (thousands of points; numpy/KD-tree/scipy in ms), SkyBoT calls (network), scoring. For a "seconds per field" target the bottleneck is IRSA cutout download and SkyBoT latency, not compute. Start CPU-only; add GPU only if running step 6 at scale.
- KBMOD itself needs aligned image stack with variance/mask/PSF and timestamps [V: input_files page]; usable but heavy dependency, pixel-space only.

## 4. Pitfalls
- Wavelength per pixel varies in each exposure (one colour per object per exposure; ~1.1-1.62 um range for detector 2 [V: sources/irsa-tut-spherex-intro.md]); an object (esp. asteroid with red slope, comet with gas lines) changes brightness frame to frame, so fixed-flux assumptions in shift-and-stack are wrong; use per-frame SNR weights, not common flux. Median template per pixel mixes wavelengths: stars/galaxies with strong colour structure leave residuals; build template only from similar-wavelength frames or work in catalog space. [NV on magnitude of effect]
- Differing PSF per detector, per position (441 ePSF regions [V: intro tutorial]) and roll angle: use per-frame PSF in matched filter; KBMOD supports per-visit PSF width [V]. Do not difference images with different PSF without matching.
- Detector edges / six detectors with different wavelength bands and seams; masked pixels; ghosts from bright sources on other FPAs (GHOST_FPA flag [V: intro tutorial]); reject candidates whose track crosses boundaries.
- Motion during exposure smears objects; exposure time not in scraped pages [NV].
- Extended comets (3I/ATLAS spatially extended at SPHEREx resolution [V: 3I page]) break point-source detection; low S/N at many wavelengths [V: 3I page].
- Observer parallax: SPHEREx in low Earth orbit; use correct observer in ephemeris for NEOs [NV].
- Slow proper-motion stars/brown dwarfs: motion within a pass is sub-pixel; use Gaia/CatWISE PM catalogs instead (WISE 0855 at ~8"/yr is user-supplied figure [NV]).
- Orbit uncertainty in SkyBoT can be hundreds-thousands of arcsec [V]; use the -filter and report ephemeris error.
